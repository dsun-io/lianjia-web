# 博客文章发布指南（AI 必读 · GEO 标准）

> 本文件是 AI 为 Lianjia Fence 网站发布博客文章时的**标准操作流程（SOP）**。
> 适用场景：新增一篇博客文章、修改已有文章、涉及 sitemap / FAQ / 结构化的改动。
> 核心原则：**代码 > 文档**，以现有文章为模板，严格对照本指南逐项执行。
>
> **本指南以 GEO（Generative Engine Optimization，生成式引擎优化）为纲**——不仅让 Google 收录，更要让 AI 搜索引擎（ChatGPT、Perplexity、Claude、Google AI Overviews、Gemini 等）**能抓取、能读懂、愿意引用**本内容作为答案来源。

## 1. 发布前：确认文章定位

每篇文章应围绕**一个明确的搜索意图 / 关键词**展开，避免多篇文章竞争同一个关键词。

| 文章类型 | 举例 | 目标关键词 |
|---------|------|-----------|
| 产品选型指南 | 牛栏网怎么选（Hinge Joint vs Ring Lock） | 长尾选型词 |
| 市场/标准攻略 | 澳新农场护栏 AS/NZS 4534 & 4680 | 地区+标准词 |
| 采购指南 | 从中国进口铁丝网 | 采购/进口意图词 |
| 安装/维护指南 | 牛栏网安装教程 | 教程词 |

**发布前确认**：
- 目标关键词没有被本站其他文章/产品页占据（用搜索确认）。
- 文章能回答买家真实问题，不是纯产品堆砌。
- 3 个作者（Vera / Leo / David）中确定一位署名作者，见 [作者人设规范](作者人设规范.md)。

## 2. 文件创建与命名

- 所有文章存放于 `blog/` 目录。
- 文件名使用**小写、连字符分隔、无扩展名后缀的 slug**，例如 `blog/import-wire-fence-from-china.html`。
- 文章 URL（canonical）使用**无 `.html` 后缀**形式：`https://lianjiafence.com/blog/<slug>`。
- 从现有任意一篇文章复制整个文件作为模板（复制 `best-field-fence-cattle-sheep-deer.html` 最完整）。

---

## 3. 页面结构模板

复制现有文章后，**逐段替换**以下内容（保持 HTML 结构不变）：

| 区块 | 说明 |
|------|------|
| `<title>` | 见 [SEO Meta 规范](#4-seo-meta-规范) |
| `meta description` / `keywords` | 见 [SEO Meta 规范](#4-seo-meta-规范) |
| `canonical` | `https://lianjiafence.com/blog/<slug>`（无 .html） |
| `og:title` / `og:description` / `og:url` / `og:image` | 与 meta 一致 |
| 正文 `<article>` / `<h1>` / `<h2>` / `<h3>` | 见 [正文内容规范](#6-正文内容规范) |
| JSON-LD | 见 [JSON-LD 结构化数据](#5-json-ld-结构化数据) |

**注意**：页面的 `<head>` 中脚本引入（swup、cursor、ga4、tailwind、blog.css 等）以及 `<style>` 设计令牌**保持原样，不要改动**。

## 4. SEO Meta 规范

### Title
- 格式：`<核心标题> | Lianjia Fence`
- 长度 ≤ 60 字符（移动端不截断）
- 主关键词靠前
- 例：`Understanding Zinc Coating for Rural Fencing | Lianjia Fence`

### Description
- 长度 140–160 字符
- 含主关键词，且自然、有行动号召
- 例：`Cattle, sheep and deer each push on a fence differently. How to match mesh, height and knot type to your stock and local conditions.`

### Keywords
- 3–6 个，主关键词 + 变体，用逗号分隔
- 不要堆砌；服务 SEO 语义即可

### Canonical
- **必须**为无 `.html` 后缀：`https://lianjiafence.com/blog/<slug>`

### GEO 关注点
- `<meta name="robots" content="index, follow">` 保持默认。
- **禁止**在正文里藏大量关键词（AI 引擎对"关键词堆砌"敏感，会判定内容质量低而不引用）。

## 5. JSON-LD 结构化数据

每篇文章必须包含 **2 个** JSON-LD 块：`BlogPosting` 和 `BreadcrumbList`。

### 5.1 BlogPosting（必填）

```json
{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "<文章标题>",
  "description": "<与 meta description 一致>",
  "image": "https://lianjiafence.com/assets/img/<文章主图>.jpg",
  "datePublished": "YYYY-MM-DD",
  "dateModified": "YYYY-MM-DD",
  "author": { "@type": "Person", "@id": "https://lianjiafence.com/#<作者id>", "name": "<作者名>", "jobTitle": "<职务>", "worksFor": { "@id": "https://lianjiafence.com/#organization" } },
  "publisher": {
    "@id": "https://lianjiafence.com/#organization",
    "logo": { "@type": "ImageObject", "url": "https://lianjiafence.com/assets/img/lianjia-fence-logo.jpg" }
  },
  "mainEntityOfPage": { "@type": "WebPage", "@id": "https://lianjiafence.com/blog/<slug>" }
}
```

**作者实体对照**（必须与 [作者人设规范](作者人设规范.md) 一致，作者 `@id` 全站唯一）：

| 作者 | `@id` | 职务 |
|------|-------|------|
| Vera Sun | `#vera` | Co-Founder |
| Leo Sun | `#leo` | Co-Founder |
| David Sun | `#david` | Export Director |

**日期规范**：`datePublished` / `dateModified` 用 **纯日期** `YYYY-MM-DD`（Google 对 BlogPosting 的日期字段接受纯日期格式）。

### 5.2 BreadcrumbList（必填）

```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Home", "item": "https://lianjiafence.com/" },
    { "@type": "ListItem", "position": 2, "name": "Blog", "item": "https://lianjiafence.com/blog/" },
    { "@type": "ListItem", "position": 3, "name": "<文章标题>", "item": "https://lianjiafence.com/blog/<slug>" }
  ]
}
```

### GEO 关注点
- **实体一致性**：`author`、`publisher`、`mainEntityOfPage` 中的 `@id` 必须与站点 `#organization` / 作者实体一致（见 [GEO品牌实体规范](GEO品牌实体规范.md)）。AI 引擎依赖稳定的实体标识来判断"这是谁在说"。
- **不加虚假结构化数据**：不写 `review` / `aggregateRating`（AI 引擎会交叉验证，虚假评分会大幅降低信任度）。

## 6. GEO 正文内容规范（核心）

> **GEO 核心目标**：让 AI 引擎能在你文章中找到**可直接引用的答案**。AI 通常偏好抓取：清晰的结论、结构化列表、FAQ、具体数据。

### 6.1 首段直接给答案（最重要）
- **第一段就要回答文章的 H1 问题**，用 2–3 句给出核心结论。AI 生成摘要时优先抓取首段。
- 例：若标题是"牛栏网 Hinge Joint 还是 Ring Lock？"，首段直接写："Hinge Joint 更灵活、吸收冲击；Ring Lock 更硬、抗高压。牛/羊用 Hinge Joint，需高压隔离的用 Ring Lock。"
- 不要在首段堆砌背景、公司介绍。答案先行。

### 6.2 用「总结框 / At a glance」
- 文章正文前放一个**可摘录摘要框**（如 `article-callout ai-summary`），用 `<ul>` 列出 3–5 条关键结论。
- 这个框是 AI 抓取"答案摘要"的最爱，已有模板（见 `australia-new-zealand-farm-fencing.html` 的 `At a glance`）。

### 6.3 层级结构便于 AI 扫描
- **H1 唯一**，就是文章标题。
- 每个大问题一个 **H2**；H2 下用小段 + 列表/表格。
- 善用 `<ul>` / `<ol>` / `<table>` 承载并列信息——AI 解析结构化内容（列表、表格）明显优于纯段落。
- 每个 H2 尽量用**问句或结论式标题**（如"Zinc coating 怎么选？"），命中 AI 引擎的问答式抓取。

### 6.4 引用具体、可验证的数据
- 用真实数据：`AS/NZS 4534`、`200 g/m²`、`2.0 mm`、`13/115/15` 等。AI 引用的内容通常是带具体数字/标准的答案。
- 避免模糊表述（"质量很好""价格便宜"），换成可量化描述。

### 6.5 FAQ 区块
- 文末加 3–5 条 **FAQ**（用站点 `faq.js` 的折叠组件），问题用买家真实会问的话。
- 若涉及站内 FAQ 知识库，可同步到 [FAQ知识库规范](FAQ知识库规范.md)。
- FAQ 是 AI 引擎直接抽取"People Also Ask"答案的富矿。

### 6.6 正文红线
- **不造假**：不写虚假评论/评分（`review`/`aggregateRating`）、不虚构规格/客户案例/认证/工厂数据。缺真实素材就留 `TODO` 占位或不写。
- **当地标准表述**：只说 `available on request / supply to ... when specified`，**绝不声称已认证**。
- **价格不写死**：用"仅供参考，以正式报价为准"。
- **不堆砌关键词**：AI 会判定为低质内容而不引用。

### 6.7 内链规范
- **产品内链**：`https://lianjiafence.com/products/<product>.html`（带 .html）。
- **文章互链**：`https://lianjiafence.com/blog/<slug>`（无后缀 canonical）。
- 内链能帮助 AI 引擎建立站点知识图谱，但**不要过度**——每篇 2–4 条相关内链即可。

## 7. AU/NZ 市场措辞规范

面向 **澳大利亚 / 新西兰** 的文章与 FAQ，必须用当地买家熟悉的术语。详细对照见仓库记忆 `/memories/repo/anz-terminology.md`，摘要如下：

| 中文 | AU/NZ 标准措辞 |

## 8. 更新博客分类页 & 总页

> ⚠️ **关键：新增文章后，除了创建文章文件，还必须更新博客列表页，否则新文章不会被索引到。**

### 8.1 找到文章归属的分类页

分类页在 `blog/` 下的 `field-fence.html`、`chain-link-fence.html`、`y-post.html`、`barbed-wire.html`。

- 在 `blog/index.html` 中，每篇文章按关键字归入对应分类。
- 在对应**分类页**（如 `blog/field-fence.html`）的文章卡片列表中，新增一条指向新文章的卡片。

### 8.2 `blog/index.html`（博客总页）

需要在两处添加新文章条目：
1. **JSON-LD `ItemList` / `BlogPosting` 列表**（约 121–132 行）—— 追加一条 `{ "@type": "BlogPosting", "headline": "...", "url": "..." }`。
2. **分类文章卡片区**（约 644–925 行的分类分组）—— 在对应分类下追加文章卡片 `<a href="/blog/<slug>.html">`。

### 8.3 分类页 `blog/<category>.html`

在对应分类的文章卡片区追加新文章卡片，标题 / 摘要 / 图片按现有卡片格式。

## 9. 更新 sitemap.xml

新增文章后，在 `sitemap.xml` 追加一条 `<url>`：

```xml
<url>
  <loc>https://lianjiafence.com/blog/<slug></loc>
  <lastmod><今天日期 YYYY-MM-DD></lastmod>
  <changefreq>yearly</changefreq>
  <priority>0.7</priority>
</url>
```

**sitemap 更新频率规则（重要）**：

| 页面类型 | changefreq | priority | 说明 |
|---------|-----------|----------|------|
| 首页 `/` | monthly | 1.0 | 品牌主入口 |
| FAQ 知识库 | weekly | 0.9 | 问答增删 |
| 产品页 / 定制页 | yearly | 0.9 | 仅优化后更新 |
| 博客总页 `/blog/` | weekly | 0.8 | 随新文章持续更新 |
| 博客分类页 | weekly | 0.8 | 随该分类新文章更新 |
| **单篇博客文章** | **yearly** | **0.7** | **发布后固定，仅修改才更新** |
| 隐私页 | yearly | 0.3 | 极低频 |

**同时更新**：新增文章后，将 `/blog/` 总页和对应**分类页**的 `<lastmod>` 更新为今天日期（因为它们会随新文章更新）。

## 10. 图片与素材

- 图片存放于 `assets/img/`，命名用连字符，如 `field-fence-hj-01.jpg`。
- 每张图片必须写 `alt` 文本（含关键词，但要自然）。
- 优先提供 `.webp` + `.jpg` 双格式，见 [图片与图标规范](图片与图标规范.md)。
- 新增图片后如需优化，运行 `npm run optimize:images`（依赖项目内的 sharp，本会话已升级到 0.35.4）。

## 12. GSC 提交与验证

1. `git add` + `git commit` + `git push origin main`。
2. 上线后（本地用 `node server.js` 预览），到 Google Search Console：
   - **网址检查**：输入新文章 URL，点「请求索引」加速收录。
   - **站点地图**：确认 `sitemap.xml` 状态为「成功」。
3. 观察 2–4 周后效果（曝光 / 排名）。

### GEO 验证（AI 引擎引用）
- **robots.txt**：确认 AI 爬虫白名单（GPTBot、OAI-SearchBot、ClaudeBot、PerplexityBot、Google-Extended 等）已允许访问（`robots.txt` 已配置，新文章无需改动，但**不要**加 `Disallow`）。
- **llms.txt**：若新增的是**重要行业文章**，可同步登记到 `llms.txt`，方便 AI 引擎发现站点内容地图。
- **手动验证**：在 ChatGPT / Perplexity / Google AI Overviews 里提问文章主题，观察是否引用本站。
