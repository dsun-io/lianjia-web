# 前端组件规范

> 目标：相同功能在全站复用同一组件/脚本，禁止页面级重复实现。

---

## 1. 共享 JS 组件清单

| 组件 | 文件 | 职责 | 引入页面 |
|------|------|------|---------|
| 导航 scrollspy | `assets/js/nav-scrollspy.js` | 页面内滚动时按 section 高亮顶部导航 | 全站（含锚点导航的页面） |
| 路径高亮 | `assets/js/swup-init.js` 内 `updateActiveNav` | 按 URL 路径决定"当前页面"高亮 | 全站（已有） |
| TOC | 各长页 `aside .toc-link` | 区块目录 + 滚动高亮 | 首页产品区等 |

**scrollspy 与路径高亮的分工**（避免冲突）：
- `updateActiveNav()` 负责**页面级**高亮（你在 /blog/ 还是 /products/）。
- `nav-scrollspy.js` 负责**页面内**高亮（你在首页的 #products 还是 #faq）。
- 当 URL 含 hash 且页面存在对应 section 时，scrollspy 结果优先；离开锚点区域后回落到路径高亮。

## 2. nav-scrollspy.js 使用约定

```html
<!-- 在引入 swup-init.js 之前引入 -->
<script src="/assets/js/nav-scrollspy.js"></script>
```

- 导航链接通过 `href="#section-id"` 与 `<section id="...">` 对应，组件自动发现，无需配置。
- 使用 `IntersectionObserver`，`rootMargin: -40% 0px -55%`，兼容 swup 页面切换（在 `content:replace` 钩子后重新初始化）。
- 高亮样式与 `updateActiveNav` 一致（`text-accent-bright` + 下划线），禁止另造样式。
- **2026-08 修订**：改用「滚动事件 + rAF 节流 + 视口 40% 判定线」实现——IntersectionObserver 的 entries 只含状态变化元素，相邻 section 交界时会误判无活动区块导致高亮错误回落。修改本组件后必须同步提升全站 script 的 `?v=` 版本号。

## 3. Tailwind 工程化铁律

- 编译命令：`npm run build:css`（`tailwindcss -i tailwind-input.css -o assets/css/tailwind.css --minify`）。
- **任何 HTML 新增/删除 Tailwind 类后，必须重编译 CSS 并随提交一起更新 `assets/css/tailwind.css`**。本次产品区布局错乱（`lg:col-span-10` 缺失）就是漏编译导致，属一级教训。
- JS 动态添加的类必须登记进 `tailwind.config.js` 的 `safelist`，并注明来源文件。

## 4. 新页面复用检查单

新建页面时按序复制：`<head>` meta 块 → favicon 链接组 → Organization schema（见 GEO 品牌实体规范）→ header/nav → footer → 共享 JS 引入顺序。禁止从旧页面"选择性复制"导致组件缺失。
